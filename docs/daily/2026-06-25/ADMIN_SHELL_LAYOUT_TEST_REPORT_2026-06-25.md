# 后台管理系统骨架布局测试报告 — 2026-06-25

> 类型: 视觉 / 交互 / 信息架构评估报告  
> 页面范围: `/admin` 后台管理系统公共骨架(Admin Shell)  
> 评估方式: 基于用户提供截图 + 已查看后台页面状态的人工 UX 评估  
> 重要说明: `/admin/settings` 页面当前尚未编写，本报告不将 settings 页面缺失视为功能 bug；本报告聚焦后台公共布局骨架问题。

---

## 一、结论摘要

当前后台管理系统已经具备 Dashboard、门店管理、文章管理、数据分析等核心模块，但公共页面骨架还没有形成稳定的后台系统布局基线。

本次截图暴露的问题不是某个单独页面的内容问题，而是所有 `/admin/*` 页面共享的 Admin Shell 问题，主要集中在两个方面：

1. 顶部 Header 空间利用率低，缺少当前页面上下文。
2. 左侧 Sidebar 与主内容区在滚动状态下缺少统一布局节奏，底部用户区显得割裂。

因此，建议在继续优化 Dashboard / 门店 / 文章 / 数据分析页面之前，先统一后台骨架布局规范。

## 三、截图问题归纳

### 问题 1：顶部 Header 过空，信息价值不足

从截图看，顶部 Header 左侧是品牌区域，右侧只有“系统管理员”，中间存在大量空白。

当前表现：

- 顶部占用高度，但没有承载足够信息。
- 用户进入不同后台页面时，顶部没有明确展示当前页面标题。
- 缺少面包屑或当前位置提示。
- Header 只展示账号身份，没有承担后台系统的导航上下文功能。

影响：

- 后台不像成熟管理系统，更像临时拼装的页面框架。
- 总部员工在不同模块之间切换时，页面方向感不足。
- 页面标题只能依赖主内容区，Header 价值偏低。

建议：

Header 应该从“空白顶部栏”升级为“当前页面上下文栏”。

推荐结构：

```txt
Header
├── 当前页面标题
├── 面包屑
└── 用户操作区
    ├── 系统管理员
    └── 可选: 退出 / 帮助 / 刷新
```

示例：

```txt
门店管理
管理后台 / 门店管理
                                  系统管理员
```

### 问题 2：Sidebar 底部用户区与主内容滚动状态割裂

从截图看，当主内容区滚动到较下方时，左侧 Sidebar 底部用户信息区与主内容区视觉上不够协调。

当前表现：

- Sidebar 看起来不像一个稳定的 `100vh` 管理侧边栏。
- 用户信息区与退出登录区域的位置显得松散。
- 主内容区滚动到底部时，Sidebar 与内容区的视觉节奏不一致。
- 左侧出现较大空洞感，降低后台系统的完整度。

影响：

- 总部员工长期使用时，会感觉后台框架“不稳”。
- 后续增加模块后，Sidebar 更容易变得混乱。
- 页面底部状态缺少统一收口。

建议：

Sidebar 应固定为完整的后台控制区。

推荐结构：

```txt
Sidebar 100vh
├── 品牌区
├── 主导航区
│   ├── Dashboard
│   ├── 门店管理
│   ├── 文章管理
│   └── 数据分析
└── 用户区
    ├── 系统管理员
    └── 退出登录
```

布局要求：

- Sidebar 高度固定为 `100vh`。
- 品牌区固定在顶部。
- 导航区占据中间剩余空间。
- 用户区固定在底部。
- 主内容区域独立滚动。
- Sidebar 不应随着主内容滚动产生视觉断裂。

## 四、settings 入口处理说明

`/admin/settings` 页面当前尚未编写，因此本报告不把它作为 bug。

但从后台产品体验角度，settings 入口有两种处理策略：

### 方案 A：暂时隐藏 settings 入口

适合当前阶段。

优点：

- 后台看起来更完整。
- 总部员工不会误点未完成模块。
- 当前可聚焦 Dashboard / 门店 / 文章 / 数据分析。

### 方案 B：保留入口，但增加占位页

适合需要提前预留系统设置模块时。

占位页内容建议：

```txt
系统设置

该模块用于后续配置后台基础信息、咨询渠道、权限与系统参数。
当前版本暂不开放。
```

本阶段建议采用方案 A：先隐藏 settings 入口。

| 优先级 | 问题 | 影响 | 建议处理 |

| P2 | 页面骨架缺少统一验收标准 | 后续页面容易各自为政 | 补充 Admin Layout SPEC |

## 六、推荐修复方案

### 6.1 先修 Admin Shell，而不是单独修页面

这次问题应该作为后台统一布局问题处理，不建议分别在 Dashboard、门店管理、文章管理、数据分析里单独修。

建议新增或更新后台布局规范：

- Admin Shell Layout
- Sidebar Layout
- Header Layout
- Main Content Container
- Admin Empty / Placeholder Page

### 6.2 Header 调整

建议 Header 改为：

```txt
左侧: 当前页面标题 + 面包屑
右侧: 当前用户 + 退出登录 / 快捷操作
```

页面标题映射示例：

| 路由 | Header 标题 | 面包屑 |
|------|-------------|--------|
| `/admin` | 仪表盘 | 管理后台 / 仪表盘 |
| `/admin/stores` | 门店管理 | 管理后台 / 门店管理 |
| `/admin/articles` | 文章管理 | 管理后台 / 文章管理 |
| `/admin/analytics` | 数据分析 | 管理后台 / 数据分析 |

### 6.3 Sidebar 调整

建议 Sidebar 使用稳定三段式结构：

```txt
品牌区
主导航区
用户区
```

视觉规则：

- 用户区固定在底部。
- 导航区使用 `flex-1` 占据剩余空间。
- 用户区与导航区之间保持清晰分隔线。
- 退出登录按钮不应漂浮或与内容滚动产生关联。

### 6.4 settings 入口处理

短期建议：

- 从 Sidebar 中暂时隐藏 settings。

中期建议：

- 当系统设置 PRD 明确后，再恢复入口。
- 或先实现占位页，避免出现未完成入口。

## 七、验收标准

后台骨架调整完成后，需要满足以下验收项：

| 验收项 | 预期结果 |
|--------|----------|
| Header 展示当前页面标题 | 每个后台页面顶部都能明确看到当前模块 |
| Header 不再大面积空白 | 顶部空间有明确的信息职责 |
| Sidebar 高度稳定 | 左侧区域始终保持完整 `100vh` 结构 |
| 用户区固定在 Sidebar 底部 | 页面滚动到底部时用户区不漂移、不割裂 |
| 主内容区独立滚动 | 内容滚动不影响 Sidebar 结构 |
| 未完成入口不暴露为可点击正式模块 | settings 未完成时隐藏或显示明确占位页 |
| 各后台页面共享同一骨架 | Dashboard / 门店 / 文章 / 数据分析布局一致 |

## 八、后续建议

建议下一步新建或更新以下 SPEC 文档：

```txt

```

该 SPEC 应定义：

- Admin Shell 的布局结构。
- Sidebar 的品牌区 / 导航区 / 用户区。
- Header 的页面标题 / 面包屑 / 用户操作。

- 未完成模块入口的展示规则。

随后再进入具体页面优化：

1. Dashboard
2. 门店管理
3. 文章管理
4. 数据分析
5. 门店新建 / 编辑表单

## 九、本次测试结论

本次截图评估确认：后台当前最需要优先处理的是公共布局骨架，而不是 settings 页面本身。

建议把本问题归档为：

```txt
后台 Admin Shell 布局基线重构
```

目标是先让后台拥有稳定、统一、可长期扩展的管理系统框架，再继续优化各业务模块页面。
