# `/agent` 门店页 UI / UX 审计与可部署改进方案

审计日期：2026-07-11  
视口：390×844、768×1024、1440×1000  
方法：Playwright Chromium 生产模式、axe WCAG 2 A/AA/2.1 AA、搜索键盘交互、公开数据与代码路径核对

## 总结

当前门店页存在发布阻断级的数据真实性问题，优先级远高于视觉改版。生产页面正在公开展示测试门店、回归数据和 E2E 数据；门店总数与省份统计互相矛盾；页面宣称“寻找离您最近的门店”，但没有定位、距离或地图能力。

在数据边界修复前，不建议继续对“全国门店网络”做视觉包装。应先把公开页面收敛到经过业务确认的真实门店，再优化搜索、地图、电话和导航链路。

## 实测摘要

- 390px 页面高 14693px，无横向溢出；第一张门店卡位于 y≈3965，约 4.7 个首屏之后。
- 768px 页面高 7885px；第一张门店卡位于 y≈2549。
- 1440px 页面高 5662px；第一张门店卡位于 y≈2059。
- 页面展示 31 个省份，其中 26 个省份为“0 家门店”，全部仍可点击。
- Hero 显示“31 个省份 · 20 家门店”；各省门店数量相加为 39 家。
- 门店区实际只渲染 20 张卡，原因是公开门店 API 默认分页/限制没有被页面正确处理。
- 页面公开出现 `D2 Test 1`、`D2 Test 2`、`TC-E1 phoneTel`、`BUG-2 回归门店`、多条 `E2E 测试门店`、`test-demo3` 等数据。
- 搜索“佛山”返回的建议中包含 `Playwright 测试门店 A1`。
- 20 张门店卡中，桌面端有 17 张复用同一张 Store Placeholder。
- 页面没有任何 `tel:` 电话链接，也没有地图/导航链接。
- 搜索建议支持 ArrowUp / ArrowDown / Escape，键盘交互基本正常。
- 未搜索到结果时，搜索框下方会显示即时空状态；但完整“搜索结果”区仍位于全部省份之后。
- axe 检出 19–20 个严重级 `color-contrast` 节点。
- 页面返回 200，无运行时 JavaScript 异常。

## P0：发布阻断项

### 1. 测试数据正在公开页面展示

当前页面展示了明显的测试、回归和 E2E 门店。静态降级文件也明确写着“Mock 数据，用于视觉展示”，但在 API/数据库不可用时会作为公开门店数据返回，其中包含南京、苏州、杭州等未确认门店。

这不仅是 UI 问题，还会造成：

- 用户拨打无效电话或前往虚构地址。
- 搜索引擎索引测试门店详情页和错误 LocalBusiness 数据。
- 品牌宣称与项目当前“仅顺德大良店真实”的业务边界冲突。
- E2E 测试持续污染生产/共享数据库。

立即可部署方案：

- 公共 API 强制只返回 `status=published AND isActive=true AND isTest=false` 的门店。
- 为门店增加明确的 `environment` 或 `dataOrigin` 字段；测试数据不能仅靠名称识别。
- E2E 使用独立测试数据库，测试结束必须清理数据。
- 静态 fallback 只保留经业务确认的顺德大良店；若真实字段未齐全，宁可显示“门店信息确认中”，不要回退到 Mock 全国门店。
- 对已生成的测试门店详情页下线并从 sitemap 移除；必要时返回 404/410。
- 上线前执行一次公开数据审计：门店名称、地址、电话、营业时间、图片、状态、经纬度、地图链接均需确认。

涉及文件：`src/app/api/stores/route.ts`、`src/lib/data.ts`、`src/lib/store.ts`、`prisma/seed.ts`、E2E fixtures/cleanup、`src/app/sitemap.ts`。

### 2. “全国门店网络”定位与当前真实业务不一致

Hero、Metadata 和页面结构都按全国连锁表达，但项目规则说明当前只有顺德大良店是真实服务中心。页面还写“寻找离您最近”，却没有用户定位、经纬度、距离计算或地图。

建议分阶段处理：

- 当前阶段：改成“顺德大良门店”或“顺德大良服务中心”，突出服务范围、真实地址、营业时间、预约和导航。
- 扩张阶段：达到多城市真实门店后，再启用“门店网络”和省市浏览。
- 只有实现定位/距离排序后才使用“离您最近”；否则改为“查找已开放门店”。
- Metadata 与页面实际覆盖范围保持一致。

涉及文件：`src/app/agent/page.tsx`、`src/app/agent/[slug]/page.tsx`、Metadata、Schema 和 sitemap。

### 3. 门店统计相互矛盾

Hero 使用 `stores.length` 作为总门店数，但 `getStores()` 没有传公开页需要的总量或分页参数，API 默认只返回前 20 条；省份卡却显示数据库中的聚合数量，合计 39 家。因此用户同时看到“20 家门店”和“广东 34 家”等矛盾信息。

可部署方案：

- `getStores()` 返回 `{ data, pagination }`，总数使用 `pagination.total`。
- 首屏只展示精选/最近门店时，标题明确写“推荐门店”，不要伪装成全部。
- 完整列表增加分页或“加载更多”，并在 URL 保存页码/筛选条件。
- 省份统计与门店列表使用完全相同的公开状态过滤条件。
- 加一致性测试：省份聚合总数、公开门店总数、分页 total 必须一致。

涉及文件：`src/lib/data.ts`、`src/app/agent/page.tsx`、`src/app/api/stores/route.ts`、`src/app/api/provinces/route.ts`。

### 4. 未知门店等级不能默认成旗舰店

`StoreLevelBadge` 和 API 映射会把缺失等级默认成 `flagship`。这会让字段不完整的测试门店或普通门店都显示“星辉旗舰店”，属于错误的品牌承诺。

可部署方案：

- 缺失等级时不显示 Badge，或明确显示“等级待确认”。
- 发布门店前将等级设为必填，并由后台校验。
- 只有通过业务审核的记录才能使用旗舰/尊享/专营等等级。

涉及文件：`src/components/agent/StoreLevelBadge.tsx`、`src/lib/data.ts`、门店发布校验。

### 5. Placeholder 被标注成“门头实景”

17 张卡复用 Placeholder，但 `alt` 统一写成“某某门店门头实景”。这对用户和屏幕阅读器都是错误描述。

可部署方案：

- 有真实图片：使用“门店外观 / 施工区 / 接待区”等准确 alt。
- Placeholder：`alt=""` 作为装饰图，同时在卡片上显示“门店图片待补充”。
- 没有真实图的门店不应被包装成已有门头实景。
- 发布流程增加门店主图完整性检查。

涉及文件：`src/components/agent/StoreCard.tsx`、门店发布校验、图片上传流程。

## P1：重构核心用户链路

### 1. 当前真实门店只有一家时，取消复杂全国查找

如果当前仅顺德大良店经过确认，最有效的页面不是 31 省份目录，而是实体门店落地页：

1. 门店实景 Hero。
2. 地址、营业时间、电话、企业微信。
3. “一键导航”“电话咨询”“微信预约”三个明确动作。
4. 可施工项目与支持车型。
5. 门店环境、工位、施工案例。
6. 服务流程与预约说明。
7. 地图和停车提示。

全国门店能力可以先作为“服务网络建设中”说明，不需要制造 31 个空入口。

### 2. 多门店阶段采用地图 + 列表

门店超过约 5 家后，桌面端建议使用左侧列表、右侧地图；移动端使用列表，并提供“地图查看”切换。

筛选建议：

- 使用当前位置。
- 省 / 市级联选择。
- 服务项目筛选。
- 距离排序。
- 营业中 / 可预约状态。

所有结果应支持 URL 深链和浏览器返回状态恢复。

### 3. 隐藏 0 门店省份

当前 31 个省份中 26 个为 0 家门店，并且全部可点击。移动端用户需要滚动约 3200px 才能看到门店列表。

建议：

- 默认只展示有已发布门店的省份。
- 无门店区域放在折叠的“即将开通”区，不可伪装成可浏览结果。
- 当用户搜索无门店地区时，提供“咨询服务范围”或“留下城市需求”，而不是引导进入空页面。

### 4. 搜索结果应紧跟搜索框

当前页面结构固定为“Hero → 31 省份 → 搜索结果/已开放门店”。用户提交搜索后，仍要穿过省份区才能看到完整结果。

可部署方案：

- `isSearching` 时隐藏省份浏览，把结果放在 Hero 后第一屏。
- 搜索成功后滚动并聚焦结果标题，同时使用 `aria-live` 宣布结果数量。
- 搜索无结果时提供“清除搜索”“联系顺德大良店”“查看服务范围”。
- 搜索错误状态增加可操作的“重试”按钮。

### 5. 增加直接电话和导航动作

门店卡显示电话和地址，但没有任何 `tel:` 或地图链接；整张卡只能进入详情。门店查找的最高频任务通常是导航和联系，不应该强制多进一层页面。

可部署方案：

- 卡片底部提供“导航”“电话”“查看详情”。
- 电话使用 `tel:`；移动端可直接拨号。
- 地址使用高德/百度地图深链或经纬度导航。
- 为避免嵌套链接，把卡片从整张 `<Link>` 改成语义化 `<article>`，标题/详情单独链接。
- 增加 `store_call_click`、`store_navigation_click`、`store_detail_click` 埋点。

### 6. 搜索增加明确提交动作

当前搜索只有输入框，没有 `<form>` 和提交按钮，依赖 Enter 或下拉建议。键盘操作虽然可用，但触屏用户的动作提示不够明确。

建议：

- 使用 `<form role="search">`。
- 增加“搜索门店”按钮，移动端可使用图标 + 可访问名称。
- 保留自动建议，支持 IME、方向键、Escape 和 Enter。
- 清空按钮命中区域从当前小尺寸提升至 44×44px。
- Loading / empty / error 使用 `aria-live="polite"`。

## P1：门店卡片信息设计

### 建议的卡片层级

1. 真实门店图片；无图时明确标注待补充。
2. 门店名称与真实等级。
3. 距离 / 城市区县 / 营业状态。
4. 支持的核心服务或车型。
5. 今日营业时间与预约提示。
6. 导航、电话、详情。

当前移动端同时在图片右上和名称下方展示等级 Badge，信息重复；保留一个即可。

### 不要依赖“旗舰优先”替代用户相关性

用户寻找门店时，距离、服务适配和营业状态通常比门店等级更重要。推荐排序应为：

1. 距离或当前城市。
2. 能否提供所需服务。
3. 当前营业/可预约状态。
4. 门店等级。

## P2：视觉与可访问性

### 对比度

- 修复 axe 检出的 19–20 个严重级对比度节点。
- 集中检查 Footer `text-zinc-500/600`、排序说明、空状态辅助文字。
- 验收标准：axe WCAG 2 AA `color-contrast` 为 0。

### 触控目标

- 移动菜单当前 40×40px，应提升至至少 44×44px。
- 搜索清空按钮约为图标加 6px padding，应提供至少 44×44px 命中区域。
- Footer 和次级链接也应保持足够行高和间距。

### 动效

- 统计圆点 `animate-pulse` 没有实际状态含义，建议删除。
- 图片 hover scale、卡片位移和箭头动画补充 `prefers-reduced-motion`。

### 性能

- 31 个省份链接和大量门店详情链接会触发较多 Next 预取；对零门店省份禁用链接，对长列表按分页加载，并考虑为非首屏链接设置 `prefetch={false}`。
- 不要一次渲染数十张相同 Placeholder；可用轻量占位块或延迟加载。

## 推荐页面结构

### 当前单店阶段

1. 顺德大良门店 Hero + 营业状态。
2. 电话 / 微信预约 / 一键导航。
3. 地图、停车和服务范围。
4. 门店实景与施工环境。
5. 支持项目和车型。
6. 施工案例与用户评价。
7. 预约说明和最终 CTA。

### 未来多店阶段

1. 当前城市 / 定位入口。
2. 搜索与筛选。
3. 地图 + 门店列表。
4. 有门店省市快捷入口。
5. 无覆盖地区需求登记。

## 开发拆分

### Slice A：数据隔离与发布安全（1–2 天）

- 公共查询只返回已发布真实门店。
- 清理测试/E2E 数据与 sitemap。
- 测试数据库隔离和自动清理。
- 修复等级默认值、Placeholder alt 和 fallback Mock。
- 添加公开数据防泄漏测试。

### Slice B：统计、分页和搜索顺序（1 天）

- 使用 pagination total。
- 省份与门店统一过滤口径。
- 搜索时隐藏省份区，结果前置。
- 增加分页或加载更多。

### Slice C：真实门店转化链路（1–2 天）

- 电话、导航、微信预约。
- 地图和营业状态。
- 卡片拆分为 article + 独立动作。
- 补转化埋点。

### Slice D：视觉与可访问性（1 天）

- 真实图片、卡片层级、删除重复 Badge。
- 对比度、触控目标、ARIA live、reduced motion。
- 390 / 768 / 1440 Playwright 回归。

## 验收标准

- 公开页、搜索建议、API、sitemap 中不存在 Test / E2E / Mock 门店。
- 只展示经过业务审核且 `published + active` 的门店。
- Hero 总门店数、列表 total、省份聚合数量一致。
- 当前业务只有顺德大良店时，不再宣称全国门店网络或“离您最近”。
- 0 门店省份不占据默认主内容，不可进入误导性空页面。
- 搜索结果在搜索框后的第一内容区出现。
- 每家公开门店至少具有真实地址、有效电话、营业时间和一个可用咨询/导航动作。
- Placeholder 不使用“门头实景”alt。
- 缺失等级不会默认显示旗舰店。
- 移动端关键动作命中区域不小于 44×44px。
- axe WCAG 2 AA 无严重级违规。
- 390 / 768 / 1440 无横向滚动。

## 风险与依赖

- 哪些门店是真实、已签约、可公开，必须由业务方书面确认。
- 地址、电话、营业时间、经纬度和门店等级需要逐店校验。
- 地图服务需要选择供应商并确认 API key、隐私告知和调用额度。
- 门店图片需要拍摄授权，人物与车牌需脱敏。
- 清理测试数据前需区分生产、开发和自动化测试数据库，避免误删真实记录。
