# `/product` 产品中心 UI / UX 审计与可部署改进方案

审计日期：2026-07-11  
视口：390×844、768×1024、1440×1000  
方法：Playwright Chromium 生产模式、axe WCAG 2 A/AA/2.1 AA、键盘交互与代码结构核对

## 结论

产品中心已经建立了“按车型 / 按项目”双入口，卡片结构完整、响应式没有横向溢出，方向是对的。但当前页面存在三类核心问题：入口状态没有统一、品牌信息重复、分类更像内部产品地图而不是车主决策工具。

建议先修复移动端入口与数据口径，再重构产品发现路径。只调整颜色和卡片样式不会显著提升用户找到适合方案的效率。

## 实测摘要

- 390px 默认“按车型”页高 3359px；切换“按项目”后内容可正常展示。
- 768px 页高 4876px；从 768px 开始取消 Tab，车型与项目全部平铺，平板竖屏信息量明显偏长。
- 1440px 页高 3865px。
- 三个视口均无横向溢出，页面返回 200，无运行时异常。
- 页面只有 2 张位图，且均为同一 Logo；主体使用 54 个 SVG / 图标 / 车辆剪影，没有真实产品、车辆或施工图。
- axe 检出 20–21 个严重级 `color-contrast` 节点。
- 移动端 Hero 的“按项目看”不能打开对应 Tab。
- Tab 点击切换正常，但方向键切换失败，Tab 与 Tabpanel 的关联 ID 不完整。

## P0：优先修复的交互与信息错误

### 1. 移动端“按项目看”实际无效

Hero 的“按项目看”是普通锚点，点击后 URL 变为 `#service-projects`，但移动端项目 Tab 仍未选中，项目面板继续 `display: none`，页面也没有滚动到有效内容。Playwright 实测：

- URL hash：`#service-projects`
- 项目面板可见：`false`
- “按项目”选中：`false`
- `scrollY`：`0`

可部署方案：

- 把 Hero 双入口与 `MobileProductContent` 的 active state 提升到同一个客户端控制器。
- Hero 点击“按项目”时同时执行 `setActiveTab("project")` 与滚动到 Tab bar。
- 使用 `?view=vehicle|project` 或 hash 初始化状态，保证刷新、分享和浏览器返回后仍保留选择。
- 桌面端仍可滚动到对应区块；移动端走状态切换，行为按视口适配。

涉及文件：`src/components/product/ProductHero.tsx`、`src/components/product/MobileProductContent.tsx`、`src/components/product/StickyTabBar.tsx`、`src/app/product/page.tsx`。

### 2. 修复统计口径和状态文案

当前 Hero 显示“车型方案地图 · 12 品牌 · 23 含整理中”。原因是 `plannedCount` 实际传入了 `ALL_SERVICES.length`，再与品牌数相加，把品牌与服务数量混成了一个总数。

页面下方同时写死“11 个热门品牌 + 13 款主流车型”，与实际展示的 12 个品牌不一致。“特斯拉 即将上线”又可以点击进入已存在的特斯拉专题页，状态感知不一致。

可部署方案：

- 分别计算并展示：`12 个品牌专题`、`N 款车型页`、`N 项已上线服务`。
- 删除跨类型相加的“23 含整理中”。
- 所有数量从 `product-routes` 动态派生，不在组件内写死。
- 统一 `live / planned / comingSoon` 定义；已可访问且有有效内容的页面不能标“即将上线”。
- 增加数据一致性测试，验证显示数量与路由表一致。

涉及文件：`src/app/product/page.tsx`、`src/components/product/ProductHero.tsx`、`src/components/product/VehicleTopicMap.tsx`、`src/lib/product-routes.ts`。

### 3. 修复 Tab 的无障碍行为

当前 Tab 按钮没有 `id`，Tabpanel 的 `aria-labelledby="vehicle|project"` 因此找不到对应节点；按下 ArrowRight 后焦点和选择都不变化。

可部署方案：

- Tab 设置 `id="tab-vehicle" / "tab-project"`。
- Tabpanel 使用 `aria-labelledby="tab-vehicle"`。
- 非激活 Tab 设置 `tabIndex={-1}`，激活项为 0。
- 实现 ArrowLeft / ArrowRight / Home / End 的 roving focus，并同步激活内容。
- Tab 切换后聚焦策略保持克制：键盘切换保留在 Tab，Hero 入口切换则滚动到内容标题。

## P1：降低产品选择成本

### 1. 删除品牌矩阵重复

Hero 已展示 12 个品牌，下方“按车型”面板又完整展示同一批品牌。390px 下用户会先扫一遍 12 品牌，再经过车辆剪影和 4 个项目入口，然后再次看到 12 品牌，重复感非常明显。

建议：

- Hero 只保留两个清晰选择：“按车型找方案”“按需求找项目”。
- 车型品牌矩阵只在车型面板出现一次。
- Hero 可保留 3–4 个热门品牌快捷入口，但必须由访问数据或业务优先级决定，不要与完整矩阵重复。
- 如果需要展示覆盖范围，改为一句“已覆盖 12 个新能源品牌”，不再塞入第二套卡片。

### 2. 从内部品类改为车主任务

“车膜系列 / 轻改装 / 实用配件 / 洗美养护 / P1 服务”符合内部业务分类，但车主通常从问题出发：刚提新车、想换颜色、老人小孩上下车不便、内饰难清理、想提升商务舒适性。

推荐的项目入口：

1. 新车保护：车衣、窗膜、底盘护板、脚垫。
2. 外观焕新：改色膜、轮毂、姿态升级。
3. 上下车与家用便利：电动踏板、脚垫、收纳。
4. 座舱舒适与商务：地板、座椅、氛围与后排便利。
5. 日常洗护：洗车、内饰清洁、膜面养护。

每个场景卡先回答“适合谁 / 解决什么问题”，进入后再展示具体产品。

### 3. 车型入口改成两阶段选择

品牌卡目前整张直接进入品牌专题；Hero 中的窄卡会截断理想车型列表，用户看不到完整车型。建议点击品牌后在当前区域展开车型，或直接提供品牌 → 车型两阶段选择：

- 第一步：品牌。
- 第二步：具体车型。
- 第三步：车型专题或推荐方案。

当前仅 12 个品牌，不必做复杂搜索；当品牌数量超过约 20 个时再增加搜索和首字母筛选。

### 4. 产品卡增加决策信息

现有卡片主要是名称和一句宣传语，难以比较。建议为已上线服务补充：

- 适用车型 / 场景。
- 施工时长范围。
- 是否需要预约。
- 质保或售后范围。
- “咨询适配”与“查看详情”两个不同层级动作。
- 若不能公开价格，可显示“到店评估报价”，不要留下价格预期空白。

### 5. 处理“整理中”服务

“更多服务正在整理”里的卡片仍然可点击，用户无法预判进入后是完整页面、预告页还是咨询页。

建议明确区分：

- 已上线：正常详情入口。
- 可咨询，方案整理中：点击打开咨询，并携带项目名称。
- 即将上线：禁用跳转或进入明确的预告页。

状态不能只靠颜色和小徽章表达。

## P1：视觉质量与品牌表达

### 1. 用真实图片替代大部分概念图

产品中心只有 Logo 位图，其余是车辆剪影、渐变、纹理和图标。对汽车改装业务来说，这不足以回答“效果怎么样、做工怎么样、是否适配我的车”。

建议：

- Hero 使用真实完成车辆或工位场景图，车辆剪影降级为车型选择辅助图形。
- 膜类卡使用车漆反光、玻璃隔热、改色实拍。
- 轻改卡使用踏板、轮毂、底盘细节实拍。
- 座舱卡使用地板、脚垫、座椅前后对比。
- 图片统一 4:3，WebP/AVIF，声明尺寸并使用响应式 `sizes`。

### 2. 减少主题效果混用

当前同一页面同时使用 cyan 玻璃、orange 金属拉丝、violet 光晕、amber 配件和 emerald 洗护，视觉差异很强，但也让页面像多个专题拼接。

建议保留橙色作为品牌/转化色，分类差异主要通过图片和小范围色标表达。统一卡片圆角、边框、阴影和标题层级，减少装饰纹理与 hover scale。

### 3. 删除重复标签

多个项目卡同时显示标题和相同的 `navLabel`，例如“隐形车衣 / 隐形车衣”“电动踏板 / 电动踏板”。若两者相同，隐藏英文/导航标签；如果要保留辅助标签，应改成“漆面保护”“上下车便利”等有区分价值的类别。

## P2：移动端与可访问性精修

### 对比度

- 修复 20–21 个 axe 严重级对比度节点。
- 集中检查 `text-zinc-500/600`、Footer、未激活 Tab、planned 服务英文标签。
- 验收标准：axe WCAG 2 AA `color-contrast` 为 0。

### 触控目标

- Hero 的“按车型找 / 按项目看”目前约 89×30px，提升至至少 44px 高。
- 移动菜单按钮 40×40px，提升至至少 44×44px。
- 桌面下拉箭头按钮约 26×26px，应扩大命中区域。

### 移动端 hover 文案

“悬停品牌色块，查看车主视角”在触屏设备上不可执行。移动端删除这句，直接在卡片上显示关键描述；桌面端可保留 hover，但 focus 也必须得到相同内容。

### 平板断点

当前 768px 即取消 Tab 并平铺全部内容，导致竖屏平板页面高达 4876px。建议将折叠/Tab 模式保持到 `<1024px`，桌面平铺从 `lg` 开始，或在平板上提供页内目录。

### 动效

为 hover scale、反光扫过、Tab 下划线和折叠动画补充 `prefers-reduced-motion`；避免纯装饰动画影响内容扫描。

## 推荐页面结构

1. Hero：产品中心价值 + 真实车辆图 + 两个入口。
2. 决策路由：按车型 / 按需求，选择状态可分享和恢复。
3. 车型模式：品牌 → 车型 → 专属方案。
4. 项目模式：新车保护 / 外观焕新 / 家用便利 / 商务舒适 / 洗美养护。
5. 真实施工案例与前后对比。
6. 施工流程、质保和适配说明。
7. 顺德大良店咨询 CTA。
8. 精简 Footer。

## 开发拆分

### Slice A：正确性与可访问性（0.5–1 天）

- 修复移动端 Hero 入口与 Tab 状态同步。
- 修复统计、品牌数量和状态文案。
- 完成 Tab ID、方向键与 focus 行为。
- 添加对应组件测试和 Playwright 用例。

### Slice B：信息架构（1–2 天）

- 删除重复品牌矩阵。
- 项目入口改为车主任务分类。
- 品牌 → 车型两阶段选择。
- 调整平板断点。

### Slice C：真实内容与视觉（2–4 天，依赖素材）

- 接入产品、车辆、施工和门店实拍。
- 统一卡片系统与色彩层级。
- 增加案例、施工时长、适用场景和咨询动作。

### Slice D：质量收口（0.5–1 天）

- 修复对比度与触控目标。
- reduced-motion。
- 390 / 768 / 1440 视觉回归和 axe 复验。

## 验收标准

- 390px 下点击 Hero“按项目看”后，项目 Tab 被选中且项目内容可见。
- Tab 支持 ArrowLeft / ArrowRight / Home / End，ARIA 引用全部有效。
- 页面所有品牌、车型、服务数字由同一数据源动态生成，不出现跨类型相加。
- 品牌状态与目标页实际完成度一致。
- Hero 与车型面板不重复完整品牌矩阵。
- 触屏设备不展示“悬停查看”类不可执行提示。
- 关键触控目标不小于 44×44px。
- axe WCAG 2 AA 无严重级违规。
- 390 / 768 / 1440 无横向滚动。
- 产品中心的每个已上线项目都能明确看到适用场景与下一步动作。

## 风险与依赖

- 场景分类需要业务确认产品之间的真实组合关系，不能仅按营销文案拼接。
- 施工时长、质保和价格范围需要门店确认后发布。
- 实拍素材需要车主授权、车牌脱敏和统一裁切规范。
- “无损安装、不伤原车结构”等承诺需要按项目和车型限定适用条件。
