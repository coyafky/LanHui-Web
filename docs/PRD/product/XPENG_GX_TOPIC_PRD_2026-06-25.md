## 1. 文档定位

本文针对用户提供的“小鹏 GX 专属升级方案”海报，规划小鹏 GX 单车型轻改专题页。

项目中已经存在小鹏在地板专题中的品牌适配内容，但还没有小鹏 GX 单车型升级方案。本文将海报中的 15 个轻改项目整理成官网可执行的页面需求，重点解决“用户看得懂、销售能转发、运营能维护、后续能埋点”的问题。

一句话定位：

> 小鹏 GX 专题页是蓝辉面向小鹏 GX 车主的单车型轻改方案页，用于集中展示车衣、隔热膜、彩绘、改色膜、电动门、平衡杆、底盘护板、360 脚垫、轮毂、门槛条、防虫网、挡泥板、钢化膜、抬头显示罩和牌照框等项目，并说明适配与施工边界。

## 2. 页面目标

### 2.1 用户目标

小鹏 GX 车主进入页面后，需要快速知道：

1. 我的小鹏 GX 可以做哪些轻改升级项目？
2. 哪些项目适合新车优先做？
3. 哪些项目偏外观个性和科技感？
4. 哪些项目属于防护、屏幕保护和日常易用升级？
5. 如何确认车型版本、适配情况和施工方案？

### 2.2 业务目标

蓝辉通过该页面实现：

1. 把“小鹏 GX 专属升级方案”转成官网可检索、可分享的内容资产。
2. 强化蓝辉对热门新能源智能车型的轻改响应能力。
3. 给销售提供可直接转发的车型专题链接。
4. 通过项目点击和项目兴趣行为判断小鹏 GX 车主更关注新车保护、外观个性、电动便利还是屏幕/内饰保护。

- 全网最低。

### 7.1 项目展示方式


- Desktop：3 列或 5 列项目网格。
- Tablet：2 列项目网格。
- Mobile：单列卡片，保留序号，方便和海报对应。

每张卡片至少包含：

- 项目名称。
- 分类标签。
- 1 句价值说明。
- 适配提示。
- 售卖状态。

### 7.2 项目状态

海报中“电动门【预售】”必须在数据和页面中单独标注。

| 状态 | 说明 | 页面表现 |
|---|---|---|
| `available` | 常规展示项目 | 正常展示项目详情 |
| `preorder` | 预售项目 | 展示“预售待确认”，并说明以到店/库存确认结果为准 |
| `pending-review` | 项目资料待核对 | 可展示但必须标注“资料待确认” |

### 7.3 项目点击行为

项目卡片点击后，一期采用展开面板，不强制每个项目做独立详情页。

| 状态 | 行为 |
|---|---|
| 默认 | 展示项目名称、分类、简短说明 |
| 展开 | 展示适合人群、注意事项、施工确认提示 |

## 12. 施工服务流程

页面应展示统一服务流程：

```text
车型确认 → 项目选择 → 到店评估 → 方案确认 → 施工安装 → 验收交付 → 售后支持
```

| 步骤 | 说明 |
|---|---|
| 车型确认 | 确认小鹏 GX 的年份、批次、版本和配置 |
| 项目选择 | 根据保护、外观、电动便利、屏幕保护等分类选择项目 |
| 到店评估 | 确认安装位、接口、材料、工期和预售/库存状态 |
| 方案确认 | 确认项目组合、施工时间和注意事项 |
| 施工安装 | 按项目标准施工，并做好车身和内饰保护 |
| 验收交付 | 检查外观、功能和安装细节 |
| 售后支持 | 提供使用注意事项和后续维护建议 |

## 19. 三棱镜验收标准

### 19.1 实现什么

- 新增小鹏 GX 单车型升级方案页面。
- 页面完整展示海报中的 15 个项目。
- 页面明确标注“电动门【预售】”状态。
- 页面按场景分类展示项目，而不是只贴海报。
- 页面提供新车保护、外观个性、科技便利三类推荐组合。

### 19.2 怎么实现

- 使用静态数据维护 15 个项目，不在组件里散落硬编码。
- 项目卡片支持分类标签、售卖状态、展开说明和项目兴趣行为。
- 海报作为素材模块展示，正文必须有 HTML 文本。
- 图片允许 `pending-review` 状态，后续再逐步匹配真实素材。

### 19.3 怎么验收

| 验收项 | 标准 |
|---|---|
| 项目完整性 | 15 个项目名称与海报一致，无遗漏、无错字 |
| 预售状态 | 电动门项目必须显示预售状态，不能当作现货项目 |
| 分类清晰 | 至少覆盖新车保护、外观个性、电动便利、底盘防护、屏幕保护、座舱维护 |
| 合规表达 | 无官方授权、原厂、不影响质保、100% 无损、性能提升等承诺 |
| 移动端可读 | 15 个项目在手机端可顺畅浏览，不横向溢出 |
| 埋点可测 | 项目点击和项目兴趣点击能带上项目名称、分类和售卖状态 |
| SEO 可读 | 主要项目以 HTML 文本存在，不只存在于图片中 |
