## 0. 参考页面原则

本 PRD 参考蔚来 ES8 页面，但不是复制 ES8 内容。L9 页面应继承 ES8 的页面模式：

- Hero 展示车型定位、项目数量、场景锚点和主 CTA。
- 项目目录以 HTML 卡片结构化呈现，不依赖长海报传达信息。
- 项目按真实用车场景重组，而不是只按海报顺序堆砌。
- 推荐组合用于销售沟通和用户决策，不写成强制套餐。
- 服务流程、FAQ、适配边界和 JSON-LD 保持单车型专题统一规范。

不采用以下做法：

- 不把完整海报作为首屏主视觉。
- 不设计独立的「海报素材展示」模块。
- 不出现“理想官方授权”“原厂配件”“100% 无损安装”“不影响质保”等未经证明的承诺。

## 1. 背景

用户提供了一张理想 L9 轻改产品目录海报，标题为「热门轻改产品目录｜理想 L9 专属升级方案」。海报包含 14 项轻改产品，覆盖车身保护、玻璃隔热、外观个性、家庭座舱、底盘防护、屏幕保护和细节防护。

现有项目已具备理想品牌入口 `/product/li-auto` 与理想 i8 占位页 `/product/li-auto/i8`，同时蔚来 ES8 已形成较完整的单车型专题页实现。理想 L9 页面应作为理想 L 系列首个大型家庭 SUV 单车型专题，把海报内容转成可检索、可分享、可扩展、可埋点的官网页面。

一句话定位：

> 理想 L9 专题页是蓝辉面向理想 L9 车主的单车型轻改方案页，用于展示 14 项热门轻改产品，并按家庭用车、新车保护、外观个性和日常防护场景引导车主确认适配与施工。

## 2. 目标

### 2.1 用户目标

理想 L9 车主进入页面后，需要快速知道：

1. 我的理想 L9 可以做哪些热门轻改项目？
2. 哪些项目适合刚提车优先做？
3. 哪些项目适合家庭用车、后排乘坐和座舱清洁？
4. 哪些项目偏外观个性、日常防护或屏幕细节保护？
5. 哪些项目需要到店确认年份、配置、接口和安装位？
6. 如何联系蓝辉确认方案和施工排期？

### 2.2 业务目标

蓝辉通过该页面实现：

1. 把「理想 L9 专属升级方案」从海报素材转成官网内容资产。
2. 承接理想 L9 大型家庭 SUV 车主的搜索与分享需求。
3. 给门店销售一条可直接转发的 L9 车型方案链接。
4. 通过项目点击、场景筛选和组合点击数据识别用户兴趣。
5. 为后续理想 L7 / L8 / L9 / MEGA 等车型专题沉淀数据结构和页面组件。

### 3.2 车型范围

一期页面只面向「理想 L9」单车型，不泛化到 L7 / L8 / i8 / MEGA。

页面需明确说明：

> 不同年份、批次、版本和配置的理想 L9 在尺寸、接口、安装位和结构上可能存在差异。页面项目只作为轻改方向参考，最终以到店确认和施工评估为准。

### 3.3 合规边界

页面不得出现以下未经证明的表达：

- 理想官方授权。
- 理想原厂配件。
- 官方同款。
- 不影响原车质保。
- 100% 无损安装。
- 永久质保。
- 全网最低。
- 性能提升、操控提升、制动提升等不可验证承诺。
- 暗示与理想汽车存在品牌合作关系。

## 11. 页面模块详细规格

| 模块 | 优先级 | 内容 | 验收重点 |
|---|---|---|---|
| Hero | P0 | 车型主视觉、14 项数量、场景锚点、CTA | 首屏清晰，不依赖完整海报 |
| 14 项项目目录 | P0 | 14 张项目卡 | 项目完整，顺序与海报一致 |
| 场景分类 | P0 | 5 类场景筛选或锚点 | 用户能按需求快速选择 |
| 推荐组合 | P1 | 4 类组合引导 | 不写成强制套餐 |
| 适配说明 | P0 | 年份、批次、版本差异提示 | 避免过度承诺 |
| 服务流程 | P1 | 7 步统一流程 | 与 ES8 页面体验一致 |
| FAQ | P1 | 适配、优先项目、单项施工、质保边界 | 解决咨询前顾虑 |
| CTA | P0 | 到店评估、返回理想系列 | 转化路径明确 |

### 11.1 图片状态规则

| 状态 | 页面表现 | 使用条件 |
|---|---|---|
| `matched` | 展示真实项目图 | 图片已经确认适配该项目 |
| `generated-preview` | 展示 AI 预览图 + 「预览图」角标 | 后续为 L9 生成 4:3 产品图 |
| `pending-review` | 展示海报裁切或占位 + 「图片审核中」标签 | 当前来源图未拆分为最终产品图 |
| `missing` | 展示统一占位卡片 | 暂无可用素材 |

当前 PRD 默认 14 项图片状态为 `pending-review`。如后续生成或补齐项目图，建议统一规格为 `1448x1086`、`4/3`，与 ES8 素材规范一致。

### 11.2 筛选与排序规则

| 能力 | 一期要求 |
|---|---|
| 默认排序 | 按海报序号 01-14 |
| 场景筛选 | 支持全部 / 新车保护 / 家庭座舱 / 外观个性 / 行车防护 / 屏幕细节 |
| 推荐组合入口 | 点击组合后高亮组合内项目 |
| 搜索 | 暂不做 |
| 价格排序 | 暂不做 |

### 11.3 移动端要求

- Hero 不超过一屏半。
- 项目卡片单列展示，触控区域足够大。
- 场景筛选可横向滚动或折叠，但不能遮挡正文。
- 图片容器固定比例，避免卡片跳动。
- CTA 在页面底部明确出现，不使用遮挡内容的浮层。

## 18. 风险与边界

| 风险 | 说明 | 处理 |
|---|---|---|
| 素材非最终施工图 | 当前只有用户海报，未拆成独立项目图 | 默认 `pending-review`，后续补真实图或生成预览图 |
| 车型适配差异 | L9 年份、版本、配置可能影响项目安装 | 所有涉及安装位项目加到店评估提示 |
| 表达过度承诺 | 底盘、平衡杆、轮毂等项目容易被理解为性能承诺 | 只写视觉、保护和适配说明，不写性能结果 |
| 品牌关系误解 | 页面使用理想车型名 | 明确为车型识别，不暗示官方合作 |
| 主题页重复 | 理想 i8、L9 都属于理想品牌 | 数据文件和页面路由分离，品牌页只做入口聚合 |

## 19. 三棱镜验收标准

### 19.1 实现什么

- 新增理想 L9 单车型升级方案页面 `/product/li-auto/l9`。
- 页面完整展示 14 项轻改项目。
- 页面按 5 类场景组织内容。
- 页面提供 4 类推荐组合。
- 页面包含适配边界、服务流程、FAQ、CTA 和 JSON-LD。

### 19.2 怎么实现

- 使用静态数据维护 14 项项目，不在组件里散落硬编码。
- 参考 ES8 页面结构：Hero、ProjectGrid、Bundles、ServiceFlow、FAQ、CTA。
- 图片状态支持 `matched` / `generated-preview` / `pending-review` / `missing`。
- 未确认图片不伪装成真实案例。
- 不实现完整海报展示模块。

### 19.3 怎么验收

| 验收项 | 标准 |
|---|---|
| 项目完整性 | 14 项项目与海报完全一致 |

| 合规表达 | 无官方授权、原厂、不影响质保、100% 无损等承诺 |
| 移动端可读 | 390px 下无横向溢出，卡片可顺畅浏览 |
| SEO 可读 | 14 项项目以 HTML 文本存在 |
| 埋点可测 | 项目点击、场景筛选、组合点击带上 key/category/scenario |
