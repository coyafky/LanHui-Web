## 1. 文档定位

本文只针对用户提供的这张“特斯拉系列轻改项目”海报，规划一个新的特斯拉系列车型专题页。

这份 PRD 不讨论整个 Product 系统升级，也不重写其他车型页面。目标是把海报里的内容转成官网页面可执行的产品需求：

- 海报表达的是：特斯拉系列车主可以做哪些轻改项目。
- 官网页面要表达的是：蓝辉能为特斯拉车主提供哪些结构化轻改方案，以及如何确认。
- 页面不能只是把海报原图贴上去，而要把海报中的项目拆成模块、分类、内容、交互和验收标准。

一句话定位：

> 特斯拉系列车型专题页是蓝辉面向 Tesla 车主的轻改项目展示页，用于集中展示车衣、膜类、座舱、底盘、电动便利和更多可选轻改项目，并说明后续确认方式。

## 2. 页面目标

### 2.1 用户目标

Tesla 车主进入页面后，需要快速知道：

1. 我的特斯拉可以做哪些轻改项目？
2. 哪些是新车最常做的基础项目？
3. 哪些是进阶的舒适、电动和智能化升级？
4. 这些项目大概解决什么问题？
5. 我怎么进一步确认适配和施工？

### 2.2 业务目标

蓝辉通过该页面实现：

1. 把“特斯拉系列轻改项目”做成一个可传播、可检索、可埋点的官网页面。
2. 强化蓝辉对新能源车型轻改的方案能力。
3. 给销售和运营一个统一页面，减少反复发送长图海报。
4. 通过项目点击和项目兴趣点击判断特斯拉车主最关注的轻改方向。

## 3. 用户与车型范围

### 3.1 目标用户

| 用户 | 需求 |
|---|---|
| Model 3 / Model Y 车主 | 关注车衣、隔热膜、改色膜、脚垫、底盘护板等基础项目 |
| Model S / Model X 车主 | 关注方向盘、仪表、电动门、后排舒适等升级项目 |
| 新车车主 | 想一次性了解新车保护和基础轻改清单 |
| 老车车主 | 想升级座舱舒适、电动便利和外观件 |
| 门店销售 | 需要把页面发给客户，作为沟通清单 |

### 3.2 车型范围

一期页面采用“特斯拉系列”表达，不做复杂年份/版本适配表。

页面需明确说明：

> 不同年份、版本和配置的 Tesla 车型在安装结构、接口、尺寸和空间上可能存在差异。页面项目作为轻改方向参考，最终以到店确认和施工评估为准。

### 3.3 不做承诺

页面不得出现以下未经证明的表达：

- Tesla 官方授权。
- 原厂配件。
- 不影响原厂质保。
- 100% 无损安装。
- 永久质保。
- 全网最低。

## 11. 施工服务流程

页面应展示蓝辉的服务流程：

```text
车型确认 → 项目选择 → 到店评估 → 施工安装 → 验收交付 → 售后支持
```

每一步建议文案：

| 步骤 | 说明 |
|---|---|
| 车型确认 | 确认 Model、年份、版本和配置差异 |
| 项目选择 | 根据用车场景选择保护、舒适或电动便利项目 |
| 到店评估 | 现场确认安装位置、接口、材料和工期 |
| 施工安装 | 按项目标准施工，过程保护车辆 |
| 验收交付 | 检查外观、功能和安装效果 |
| 售后支持 | 提供使用注意事项和后续维护建议 |

## 15. 数据结构建议

建议新建静态数据文件：

`src/lib/tesla-products.ts`

核心结构：

```ts
export type TeslaProjectPriority = "featured" | "optional";
export type TeslaProjectCategory =
  | "paint_protection"
  | "film_style"
  | "chassis_protection"
  | "cabin_comfort"
  | "electric_convenience"
  | "infotainment"
  | "exterior_parts"
  | "storage_accessory";

export type TeslaProject = {
  key: string;
  name: string;
  category: TeslaProjectCategory;
  priority: TeslaProjectPriority;
  order: number;
  summary: string;
  applicableModels?: string[];
  imageStatus: "matched" | "pending-review" | "missing";
};
```

一期可以先不为每个项目准备独立图片，允许 `imageStatus = "pending-review"`。
