# 蓝辉官网页面级 PRD 总览

> **版本**: v1
> **日期**: 2026-06-29
> **上位文档**: `docs/PRD/00_MASTER_PRD.md`
> **用途**: 为不同页面族建立统一 PRD 口径。单页详细实现仍可拆到独立 PRD，但不得违背本文的页面目标、表达标准和验收标准。

---

## 1. 背景

现有 PRD 文档数量多、日期跨度大，部分页面已经实现多轮迭代，但页面目标和表达标准没有同步收敛。特别是产品中心和车型专题扩张后，用户会在“按车型找”“按项目找”“整理中专题”“推荐组合”之间跳转，缺少统一的页面级判断标准。

本文先为主要页面族建立页面级 PRD，后续可按优先级拆成更细的独立 PRD。

---

## 2. 目标

- 用户目标：进入任意页面后 5 秒内知道本页能解决什么问题，以及下一步应点击哪里。
- 业务目标：把公开站转化路径统一为“了解蓝辉 → 找方案 → 看门店/联系 → 咨询到店”。
- 工程目标：让页面 PRD 与当前 Next.js 16 App Router、静态 fallback、CMS、API 结构一致。
- 可量化结果：核心公开页 390px / 768px / 1440px 浏览器检查无布局阻断；页面级 PRD 覆盖首页、产品中心、服务线、品牌/车型、门店、资讯、联系、admin。

---

## 3. 非目标

- 不在本文写每个车型项目的完整 SKU 明细。
- 不新增数据库字段。
- 不调整 admin 权限模型。
- 不承诺价格、官方授权或未验证施工效果。
- 不替代已有产品专题 PRD；本文只定义页面族级约束。

---

## 4. 页面 PRD

### 4.1 首页 `/`

| 项 | 内容 |
|---|---|
| 页面任务 | 建立品牌第一印象，分流到产品中心、门店和咨询 |
| 核心用户问题 | “蓝辉是谁？做什么？我该从哪里开始？” |
| 首屏表达 | 品牌名 + 新能源轻改/车身膜服务定位 + 真实视觉资产 + 主 CTA |
| 主 CTA | 查看产品中心 |
| 次 CTA | 查看门店 / 微信咨询 |
| 主要组件 | `Header`、`Hero`、`WhyChooseUs`、`CoreServices`、`ProductsQuickEntry`、`Footer` |

验收标准：

- [ ] H1 是品牌名或清晰品牌 offer。
- [ ] 首屏不只依赖渐变背景，必须有真实产品、施工、门店或品牌视觉资产方案。
- [ ] 用户能从首屏进入 `/product` 和门店/咨询路径。
- [ ] 移动端 CTA 不换行溢出。

### 4.2 产品中心 `/product`

| 项 | 内容 |
|---|---|
| 页面任务 | 做导购分流，不展示所有细节 |
| 核心用户问题 | “我应该按车型找，还是按项目找？” |
| 首屏表达 | 产品中心 + 按车型找方案 / 按项目看服务 |
| 主 CTA | 按车型找 |
| 次 CTA | 按项目看 |
| 数据源 | `src/lib/product-routes.ts` |

验收标准：

- [ ] 页面明确分成“按车型找”“按项目找”“推荐组合”。
- [ ] `planned` 内容默认收敛，不抢占 P0 入口。
- [ ] 移动端使用 tab、锚点或折叠减少长滚动。
- [ ] 桌面端首屏不堆叠超过 3 个同等权重入口。
- [ ] JSON-LD ItemList 路由来自当前 live routes。

### 4.3 服务线页面 `/product/<service>`

适用：车衣、窗膜、改色膜、电动踏板、轮毂、底盘、地板、脚垫、商务舒适等。

| 项 | 内容 |
|---|---|
| 页面任务 | 解释单一服务项目价值、适配人群、施工边界和咨询路径 |
| 核心用户问题 | “这个项目解决什么问题？适合我的车吗？施工要注意什么？” |
| 首屏表达 | 服务名 + 用户痛点 + 结果价值 |
| 主 CTA | 微信咨询项目 |
| 次 CTA | 查看适配车型 / 查看门店 |

验收标准：

- [ ] 不只展示产品名，必须解释场景、收益和注意事项。
- [ ] 有服务流程或施工边界说明。
- [ ] 有车型/门店/咨询内链。
- [ ] 移动端参数表或对比表可读，不强迫用户横向猜内容。

### 4.4 品牌专题 `/product/<brand>`

适用：问界、小米、极氪、理想、特斯拉、小鹏、腾势、岚图、乐道、高山、智界、蔚来。

| 项 | 内容 |
|---|---|
| 页面任务 | 聚合该品牌车型入口，给出品牌车主的改装方向 |
| 核心用户问题 | “我的品牌有哪些车型方案？哪些项目最常见？” |
| 首屏表达 | 品牌名 + 车型矩阵 + 3 个高频升级方向 |
| 主 CTA | 选择车型 |
| 次 CTA | 咨询品牌方案 |

验收标准：

- [ ] 品牌页不能只是 TopicBanner 列表。
- [ ] 至少展示车型入口、核心项目方向、咨询 CTA。
- [ ] 品牌色和视觉元素能区分品牌，不只换标题。
- [ ] `planned` 车型要标清状态，不伪装成已完整上线。

### 4.5 车型页 `/product/<brand>/<model>`

| 项 | 内容 |
|---|---|
| 页面任务 | 给单车型车主一页式项目建议 |
| 核心用户问题 | “这台车优先做什么？哪些项目适合我？” |
| 首屏表达 | 车型名 + 本车型优先升级摘要 |
| 主 CTA | 咨询本车型方案 |
| 次 CTA | 返回品牌页 / 查看门店 |

验收标准：

- [ ] 首屏展示 3 个以内的优先项目摘要。
- [ ] 项目按场景分组：新车保护、舒适升级、外观升级、实用配件等。
- [ ] `imageStatus: pending-review | missing` 必须有明确占位 UI 和 alt，不允许空白。
- [ ] 移动端长列表必须有锚点、折叠或分段导航。
- [ ] FAQ 回答适配、施工、售后、到店前准备。

### 4.6 门店网络 `/agent`

| 项 | 内容 |
|---|---|
| 页面任务 | 帮用户找到真实可服务门店 |
| 核心用户问题 | “附近有没有店？怎么去？怎么联系？” |
| 首屏表达 | 门店网络 + 当前重点门店 + 地区选择 |
| 主 CTA | 查看顺德大良店 |
| 次 CTA | 微信咨询 |

验收标准：

- [ ] 不展示测试污染门店。
- [ ] 门店卡片必须有名称、城市、地址、电话或明确联系方式。
- [ ] 省市筛选在移动端可操作。
- [ ] 门店详情有地址、营业时间、电话、导航/咨询路径。

### 4.7 资讯 `/news`

| 项 | 内容 |
|---|---|
| 页面任务 | 承载品牌动态、知识内容和 SEO 长尾 |
| 核心用户问题 | “蓝辉有什么新内容？这类产品怎么选？” |
| 主 CTA | 阅读文章 |
| 次 CTA | 咨询相关服务 |

验收标准：

- [ ] 列表文章点击后详情可达。
- [ ] 详情页有标题、发布日期、分类、正文、返回列表。
- [ ] 文章正文不能只有摘要或空内容。
- [ ] Markdown 渲染样式在移动端可读。

### 4.8 联系页 `/contact`

| 项 | 内容 |
|---|---|
| 页面任务 | 汇总真实联系方式和到店路径 |
| 核心用户问题 | “我怎么联系蓝辉？什么时候能去？” |
| 主 CTA | 微信咨询 |
| 次 CTA | 查看门店 |

验收标准：

- [ ] 不展示假 400、占位二维码或未验证账号。
- [ ] 电话、地址、营业时间来自可信数据源。
- [ ] 移动端点击电话和地图路径可用。

### 4.9 Admin 页面族 `/admin`

| 页面 | 任务 |
|---|---|
| `/admin/login` | 登录、失败反馈、重定向 |
| `/admin` | 运营摘要、待办、KPI、快捷入口 |
| `/admin/analytics` | 访问、咨询、门店兴趣趋势 |
| `/admin/articles` | 文章 CRUD 和发布状态管理 |
| `/admin/stores` | 门店 CRUD、状态、图片、地区 |

验收标准：

- [ ] `(dashboard)` 页面必须 `auth()` 保护。
- [ ] editor/admin 权限边界符合 PRD。
- [ ] 表格页面有空态、错误态、加载态或提交反馈。
- [ ] 移动端至少能完成查看和核心操作，不出现内容遮挡。

## 6. 验收标准

- [ ] 页面级 PRD 覆盖所有核心页面族。
- [ ] 每个页面族都有用户问题、页面任务、CTA、验收标准。
- [ ] 后续单页 PRD 不与本文冲突。
- [ ] UI 改版必须补 390px、768px、1440px 浏览器检查。
- [ ] 产品专题缺图状态必须显式处理。

---

## 7. 验证命令

文档更新本身不需要运行完整测试。若本 PRD 驱动代码改版，至少执行：

```bash
npm run build
npm run lint
npm test
```

涉及类型或 API：

```bash
npm run typecheck
npx vitest run <changed-test-file>
```

涉及 UI：

- 390px mobile
- 768px tablet
- 1440px desktop

---

## 8. 风险边界

| 风险 | 边界 |
|---|---|
| 内容真实性 | 不写未验证价格、资质、合作关系 |
| 图片资产 | 缺图状态必须明确，不能假装真实案例 |
| 路由漂移 | 新增产品路线必须同步 `src/lib/product-routes.ts` |
| Build | 公开站 SSG 不能依赖 Postgres |
| Admin | 写操作不能绕过角色校验 |
| 文档债 | 旧 PRD 可保留，但 Master PRD 和本文为当前页面级准绳 |
