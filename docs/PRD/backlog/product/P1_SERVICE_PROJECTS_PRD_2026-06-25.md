## 2. 核心判断

P1 项目不能简单理解为“所有海报里出现过的项目都建一个页面”。这样会产生大量薄内容页面，用户看了也没有决策价值，后续维护会很重。

更合理的做法是三层：

1. **独立服务页**：高频、可解释、可验收、有真实施工价值。
2. **聚合服务页**：单个项目内容不够厚，但一组项目能形成场景方案。
3. **车型页项目卡 / 暂缓独立成页项**：小配件、低决策成本项目，不急着独立成页，也不在产品页内设置私有操作。

## 3. P0 与 P1 边界

### 3.1 P0 已有核心服务页

| 项目 | Route | 定位 |
|---|---|---|
| 隐形车衣 / 车衣 | `/product/ppf` | 新车漆面保护 |
| 汽车窗膜 / 隔热膜 | `/product/window-film` | 隔热、防晒、隐私 |
| 改色膜 | `/product/color-film` | 外观风格表达 |
| 电动踏板 | `/product/electric-steps` | 高底盘 SUV / MPV 上下车便利 |
| 轮毂升级 | `/product/wheels` | 外观姿态与数据匹配 |
| 底盘升级 | `/product/chassis` | 底盘护板、平衡杆、底盘防护相关 |

### 3.2 P1 项目定义

P1 项目是指：

- 在多个车型海报中反复出现；
- 车主经常会问；
- 对内容分流有帮助；
- 但暂时不一定都有足够内容支撑独立页面。

## 4. P1 项目分层规划

### 4.1 A 类：建议独立成页

这些项目具备独立用户需求、施工解释空间和验收标准，建议作为 P1 第一批。

| 项目 | 建议 Route | 理由 | 页面优先级 |
|---|---|---|---|
| 360 软包脚垫 / 三防软包脚垫 | `/product/floor-mats` | 多车型高频出现，用户容易理解，适合新车保护组合 | P1-A |
| 铝地板 / 木地板 | `/product/flooring` | 已有专题，可升级为地板服务页，适合 MPV / SUV | P1-A |
| 底盘护板 | `/product/skid-plate` 或 `/product/chassis#skid-plate` | 高频项目，但可先并入底盘页，内容成熟再拆 | P1-A |
| 商务舒适升级 | `/product/business-comfort` | 小桌板、腿托、后排娱乐、氛围灯等适合聚合成场景页 | P1-A |

> 建议：第一批不要超过 4 个。先把 P1-A 做扎实，别贪多。

### 4.2 B 类：适合聚合展示，不建议单独成页

这些项目单独做页面会偏薄，但组合起来很有业务价值。

| 项目 | 建议归属 | 页面策略 |
|---|---|---|
| 小桌板 | 商务舒适升级 | 作为 `/product/business-comfort` 模块 |
| 后排娱乐电视 | 商务舒适升级 | 作为商务升级重点模块 |
| 氛围灯 | 商务舒适升级 / 内饰氛围 | 需要真实案例后再考虑独立 |
| 腿托 | 商务舒适升级 | 结合座椅舒适改造说明 |
| 智能头枕 | 商务舒适升级 | 车型页展示，聚合页解释 |
| 流媒体后视镜 | 安全便利升级 | 可先放车型页，后续与抬头显示/显示保护聚合 |
| 星空顶 / 星空膜 | 内饰氛围升级 | 不急独立，先看素材储备 |

### 4.3 C 类：小配件 / 暂缓独立成页项

这些项目可以出现在车型页和入口页，但不建议早期独立建 SEO 页。

| 项目 | 原因 | 页面策略 |
|---|---|---|
| 门槛条 | 决策成本低，内容薄 | 车型页项目卡 |
| 牌照框 | 内容薄，搜索价值低 | 车型页项目卡 |
| 钢化膜 / 屏幕保护 | 可作为小配件 | 车型页项目卡 |
| 防虫网 | 实用但内容有限 | 车型页项目卡 |
| 挡泥板 | 实用但内容有限 | 车型页项目卡 |
| 四门密封条 | 适配依赖车型 | 车型页项目卡 |
| 内饰硅胶件 | 小配件属性强 | 车型页项目卡 |
| 尾箱垫 | 小配件属性强 | 车型页项目卡 |
| 防护垫系列 | 适合放在脚垫/内饰防护聚合中 | 不单独 |

## 5. P1 独立服务页统一 PRD 结构

每一个 P1 独立服务页都必须回答 5 个问题：

1. 这个项目解决什么问题？
2. 哪些车型 / 哪些车主适合做？
3. 蓝辉怎么判断适配和施工方式？
4. 施工完成后怎么验收？
5. 用户不确定时如何继续了解？

### 5.1 页面模块标准

```text
P1 服务项目页
├── 适合哪些车主
├── 适合哪些车型
├── 项目价值：解决什么痛点
├── 方案类型：基础 / 进阶 / 高阶（不写固定价格）
├── 施工边界：哪些情况必须到店确认
├── 施工流程：沟通 → 看车 → 方案 → 施工 → 验收
├── 验收标准：外观 / 功能 / 安全 / 清洁
├── 车型案例入口：回链到车型页
├── 常见问题 FAQ
```

### 5.2 Hero 规范

| 字段 | 写法 |
|---|---|
| H1 | `{项目名}｜蓝辉轻改` |
| 副标题 | 用一句话说明项目价值，不堆参数 |

示例：

> 360 软包脚垫不只是“垫子”，它解决的是新车地毯保护、日常清洁、家用通勤和后排乘坐舒适的问题。

### 5.3 适合人群模块

每个页面至少写 4 类人群：

| 人群 | 示例 |
|---|---|
| 新车车主 | 刚提车，想先做基础保护 |
| 家庭用户 | 有老人、小孩，重视清洁和舒适 |
| 商务接待用户 | 后排使用频繁，重视质感 |
| 长途出行用户 | 希望耐脏、易清洁、耐用 |

### 5.4 适合车型模块

不能写“所有车型通用”。推荐写：

- 常见适配：问界 M6/M7/M8、小米 YU7、理想 i8、岚图梦想家、高山 8 等；
- 实际适配以车型、年款、配置和实车状态为准；
- 未确认车型通过首页或全站 Header/Footer 入口继续了解。

### 5.5 项目价值模块

每个项目都用“痛点 → 价值”表达，不写空泛卖点。

| 痛点 | 页面表达 |
|---|---|
| 原车地毯难清洁 | 防护覆盖、日常更好打理 |
| 后排使用频繁 | 提升脚感和乘坐观感 |
| 雨天泥沙 | 易清洁、防污能力更重要 |
| 商务接待 | 视觉更完整，车内更整洁 |

### 5.6 方案类型模块

不建议早期写死价格。可以写方案类型：

| 类型 | 说明 |
|---|---|
| 基础实用型 | 解决保护和清洁 |
| 家用舒适型 | 更重视脚感、包覆和视觉统一 |
| 商务质感型 | 更重视材质、颜色、整体内饰质感 |

### 5.7 施工边界模块

P1 项目必须写清边界，避免销售话术过满。

统一表达：

- 具体适配需确认车型、年款、座椅布局和原车配置；
- 涉及电路、座椅、门体、屏幕类项目必须到店确认；
- 不承诺所有车型都可做同一方案；
- 不承诺“不影响质保”，只说明施工方式和注意事项。

### 5.8 验收标准模块

| 验收维度 | 标准 |
|---|---|
| 外观 | 边缘整齐、颜色与内饰协调、无明显翘边 |
| 功能 | 不影响座椅滑动、开关门、踏板、储物等原车功能 |
| 安全 | 不遮挡安全带、气囊、踏板操作和必要传感器 |
| 清洁 | 交付前清理施工痕迹，提示后续维护 |
| 适配 | 与车型结构匹配，不强行安装 |

## 6. P1-A 页面细化规划

### 6.1 360 软包脚垫 / 三防软包脚垫

| 字段 | 内容 |
|---|---|
| 建议 Route | `/product/floor-mats` |
| 页面定位 | 新车基础保护 + 家用清洁便利 |
| 关联车型 | 问界 M6/M7/M8、小米 YU7、理想 i8、岚图梦想家、高山 8 |
| 推荐组合 | 新车基础保护、商务舒适升级 |
| 必须强调 | 适配车型和座椅布局需要确认 |

模块重点：

- 为什么新车建议先做脚垫；
- 360 软包与普通脚垫差别；
- 三防含义要解释为防污、防水、易清洁，不做夸张承诺；
- 二排 / 三排 / 后备箱不同区域的适配。

### 6.2 铝地板 / 木地板

| 字段 | 内容 |
|---|---|
| 建议 Route | `/product/flooring` |
| 页面定位 | MPV / SUV 后排空间质感升级 |
| 当前基础 | 已有 [FLOORING_TOPIC_PRD_2026-06-20.md](./FLOORING_TOPIC_PRD_2026-06-20.md) |
| 推荐处理 | 从“主题专项”升级为“地板服务项目页 + 车型案例入口” |
| 必须强调 | 地板安装不能影响座椅轨道、脚踏、储物和安全结构 |

模块重点：

- 木地板 / 铝地板适合哪些车型；
- 商务、家庭、露营等场景；
- 与脚垫、门槛条、氛围灯的组合关系；
- 验收要关注边缘、轨道、异响、清洁。

### 6.3 底盘护板

| 字段 | 内容 |
|---|---|
| 建议 Route | 先用 `/product/chassis#skid-plate`，后续再拆 `/product/skid-plate` |
| 页面定位 | 新能源车底盘防护、日常通勤防刮蹭 |
| 关联车型 | 小米 YU7、问界 M6/M7/M8、理想 i8、乐道 L90、小鹏 GX |
| 推荐处理 | 先作为底盘升级页重点模块 |
| 必须强调 | 安装不应影响散热、排水、检修和原车安全结构 |

模块重点：

- 新能源车底盘为什么容易被关注；
- 护板材质和安装方式不能过度承诺；
- 到店检查底盘结构和安装位；
- 验收关注固定点、异响、离地间隙。

### 6.4 商务舒适升级

| 字段 | 内容 |
|---|---|
| 建议 Route | `/product/business-comfort` |
| 页面定位 | MPV / 大六座 SUV 后排舒适与质感升级 |
| 包含项目 | 小桌板、腿托、后排娱乐、氛围灯、智能头枕、星空顶/星空膜 |
| 关联车型 | 问界 M7/M8、理想 i8、岚图梦想家、高山 8、腾势 D9 |
| 必须强调 | 涉及电路、座椅、门体、屏幕的项目必须到店确认 |

模块重点：

- 按用户场景讲：家庭出行、商务接待、长途乘坐；
- 不把每个小项目拆成薄页面；
- 说明哪些项目可组合、哪些必须单独确认；
- 对电动门、后排娱乐等高风险项目设置更严格确认边界。

## 8. 与车型页的关系

P1 项目页不是替代车型页，而是和车型页互相回链。

| 页面 | 应该怎么链接 |
|---|---|
| 车型页 | 项目卡片若已有服务页，则链接到服务页；没有服务页则停留在卡片详情 |
| P1 服务页 | 展示“常见适配车型”，链接回车型页 |
| `/product` 入口页 | 展示 P1 项目状态，不让用户误以为所有页面已完成 |

示例：

```text
/product/wenjie/m8
└── 三防软包脚垫 → /product/floor-mats

/product/floor-mats
└── 常见适配车型 → /product/wenjie/m8
```

## 9. 合规边界

P1 项目尤其容易出现销售夸张表达，必须避免：

- “所有车型通用”
- “100% 无损”
- “不影响质保”
- “永久质保”
- “原厂级”
- “官方同款”
- “全网最低”
- “绝对安全”

推荐表达：

- “需结合车型、年款和配置确认”
- “优先选择不破坏原车结构的方案”
- “具体施工方式以到店检查为准”
- “交付时按功能、外观、安全边界共同验收”

## 11. 三棱镜验收

### 11.1 实现什么

| 模块 | 结果 |
|---|---|
| P1 分类 | 明确哪些独立成页、哪些聚合、哪些暂缓独立成页 |
| 页面模板 | 每个 P1 服务页都有统一内容结构 |
| 车型回链 | P1 服务页能回链常见车型页 |
| 合规边界 | 不出现绝对化承诺 |

### 11.2 怎么实现

| 阶段 | 内容 |
|---|---|
| Phase 1 | 在 `/product` 入口页展示 P1 项目卡片和状态 |
| Phase 2 | 先升级 `/product/flooring`，并新建 `/product/floor-mats` PRD |
| Phase 3 | 将底盘护板作为 `/product/chassis` 内重点模块 |
| Phase 4 | 新建 `/product/business-comfort` 聚合页 PRD |
| Phase 5 | 根据真实素材再决定是否拆分更多独立页 |

### 11.3 怎么验收

| 验收项 | 标准 |
|---|---|
| 页面数量控制 | P1 第一批独立/聚合页面不超过 4 个 |
| 内容厚度 | 每个独立页至少包含适合人群、适配车型、施工边界、验收标准、FAQ |
| 回链完整 | P1 服务页与至少 3 个车型页互相链接 |
| 状态清晰 | planned 项目不出现 404 链接 |
| 合规通过 | 无绝对适配、绝对无损、不影响质保等话术 |
| 移动端可读 | 卡片与 FAQ 在 390px 下无横向滚动 |
