## 1. 第一性原理判断框架

汽车轻改官网的本质不是“展示很多项目”，而是降低车主从陌生到咨询的心理成本。用户进入页面时只会连续问 5 个问题：

| 顺序 | 用户内心问题 | 页面必须给出的答案 |
|---|---|---|
| 1 | 这是做什么的？ | 品牌/页面对象 + 服务类别 |
| 2 | 跟我的车/需求有关吗？ | 车型、项目、场景入口 |
| 3 | 为什么可信？ | 真实门店、真实案例、工艺、资质、流程 |
| 4 | 我该怎么选？ | 少量优先级建议，而不是全量清单 |
| 5 | 下一步怎么行动？ | 微信、电话、门店、车型咨询 CTA |

因此本次逐帧审计不只看视觉美观，而看每一屏是否推动用户往下一个问题走。

|---|---:|---|---|

| `/product/wenjie` | 74 | 车型表达明显变好 | Hero 有车图和车型入口，但项目很多，咨询路径弱 |
| `/product/xiaomi` | 66 | 内容密度高但决策弱 | 中段大量标签，用户难判断优先级 |
| `/product/zeekr` | 58 | 移动端表达断层 | 多帧无 heading，缺图卡造成半成品感 |
| `/agent` | 35 | 当前不适合上线 | 测试门店污染直接破坏信任 |

P0:

- `/agent` 和 `/news` 出现测试内容，品牌信任被直接破坏。
- `/product/zeekr` mobile 中段有多帧无可见 heading，用户不知道自己处在哪个内容段。

P1:

- 首页和产品中心缺少真实视觉资产，首屏仍像“模板官网”。
- 产品中心移动端过早出现“更多车系专题整理中”，分流主任务被稀释。
- 车型页项目过多，缺“首选 3 项”决策层。

## 3. 页面逐帧审计

### 3.1 首页 `/`

证据:

- Desktop: `screenshots/2026-06-29-frame-audit/desktop/home-frame-01.png`
- Mobile: `screenshots/2026-06-29-frame-audit/mobile/home-frame-01.png`

逐帧判断:

| 帧 | 当前表达 | 好/坏 | 优化方向 |
|---|---|---|---|
| 首屏 | H1“蓝辉轻改” + 源头工厂 + 企业微信 CTA + 产品中心 CTA | 好: 用户知道品牌和服务范围；坏: 背景主要是渐变，缺真实产品/门店证据 | 首屏加入真实施工/门店/产品图；主 CTA 改为“按车型找方案”，微信作为次 CTA |
| 中段 | 为什么选择、核心服务 | 好: 有能力点；坏: 仍偏内部话术，“专业工艺/优质材料”缺证据 | 每个能力点绑定可验证证据，如施工流程、质保说明、门店实拍 |
| 产品入口 | 6 个产品卡 | 好: 入口完整；坏: 按内部品类，不按车主问题 | 改为“新车保护、隔热隐私、外观风格、上下车便利、底盘防护、车型方案” |

语言重组建议:

- 当前: “源头工厂制造能力，新能源车主一站式升级服务”
- 建议: “刚提新能源车，先把保护、隔热和实用升级选清楚”
- 原因: 用户不是先关心工厂规模，而是先关心“我的车该做什么”。工厂能力应作为第二层证据出现。

### 3.2 产品中心 `/product`

证据:

- Desktop: `screenshots/2026-06-29-frame-audit/desktop/product-frame-01.png`
- Mobile: `screenshots/2026-06-29-frame-audit/mobile/product-frame-03.png`

逐帧判断:

| 帧 | 当前表达 | 好/坏 | 优化方向 |
|---|---|---|---|
| 首屏 | 车辆剪影 + 材质切片 + 12 品牌矩阵 | 好: 信息架构先进；坏: 桌面首屏左右信息都很多，主行动不够突出 | 首屏只保留两个大决策按钮：“我按车型找”“我按项目找” |
| 移动中段 | “更多车系专题整理中”提前出现 | 坏: 用户还没完成 P0 决策，就看到大量 planned 内容 | planned 内容移动端默认折叠到末尾 |
| 后段 | 品牌专题 banner 列表 | 好: SEO 和入口丰富；坏: 视觉像上线内容，不像“整理中” | planned 卡片降权，标清“可咨询，不是完整页面” |

语言重组建议:

- 当前: “按车型找方案，按项目看服务”
- 建议加一个选择句: “不知道先做什么？先选车型；已经明确项目？直接看服务。”
- 原因: 产品中心不是内容页，是决策分流页。

### 3.3 问界专题 `/product/wenjie`

证据:

- Mobile: `screenshots/2026-06-29-frame-audit/mobile/wenjie-frame-01.png`

逐帧判断:

| 帧 | 当前表达 | 好/坏 | 优化方向 |
|---|---|---|---|
| 首屏 | H1 问界系列项目升级方案 + 34 项 + M6/M7/M8 入口 + 车辆预览图 | 好: 比旧审计明显更完整，车型入口清楚 | 增加“问界车主优先看这 3 项” |
| 中段 | 热门项目、场景、更多选择 | 好: 覆盖全面；坏: 项目过多，用户需要自己判断 | 按“新车先做/家庭后排/外观升级/户外露营”给推荐顺序 |
| 末段 | 车型 CTA | 好: 有咨询收口；坏: 到达太晚 | 在每个项目组后增加轻 CTA：“带车型问价格/适配” |

语言重组建议:

- 当前: “34 个升级项目 / 3 个车型”

| 帧 | 当前表达 | 好/坏 | 优化方向 |
|---|---|---|---|
| 首屏 | “汽车窗膜” + “不只是为了隔热” | 好: 直接抓住用户误区和痛点 | 可以在首屏加“热/晒/隐私/眩光”四个快捷问题 |

## 4. 横向表达问题

### 4.1 CTA 被导航文本稀释

`frames.json` 中大量帧的可见 CTA 首先抽到的是 Header 菜单：`首页 / 产品中心 / 隐形车衣 / 汽车窗膜...`。这说明页面真实 CTA 在很多帧里不够突出。

修复:

- 每个核心 section 底部放小 CTA。
- 移动端底部可考虑固定“咨询车型方案 / 查看门店”。
- Header 下拉菜单文本不要在未展开时成为主要可见 CTA。

### 4.2 “项目很多”替代了“帮我选择”

问界、小米、极氪等页面都证明项目库丰富，但用户需要的是优先级。

修复:

- 每个车型页首屏固定三项:
  - 新车先做
  - 家用舒适
  - 外观升级
- 商品清单放第二层，不抢首屏。

### 4.3 真实证据不足

首页、品牌页、产品中心大量依赖渐变、剪影、预览图。对汽车服务行业来说，真实门店、真实施工、真实交付比视觉装饰更能建立信任。

修复:

- 首页首屏/第二屏补真实门店或施工图。
- 品牌页补“顺德大良店实拍 + 服务台/施工区/交付区”。
- 车型页对 AI 预览图明确标注，并优先展示真实案例。

### 4.4 测试内容污染是品牌 P0

`/agent`、`/news` 当前暴露测试数据。用户不会理解这是测试环境，他们只会判断品牌不专业。

修复:

- 公开 API 加测试数据过滤。
- seed/e2e 数据使用不可发布状态。
- CMS 列表和公开列表分离测试数据。

## 5. 建议改版顺序

| 优先级 | 改动 | 目标 |
|---|---|---|
| P0 | 清理 `/agent`、`/news` 测试内容 | 恢复基础可信度 |
| P0 | 修复 `/product/zeekr` mobile 无 heading/缺图大块 | 防止车型页半成品感 |
| P1 | 产品中心移动端 planned 内容后置 | 让用户先完成车型/项目分流 |
| P1 | 首页首屏加入真实视觉资产 | 从模板感变成真实品牌 |
| P1 | 车型页加“首选 3 项” | 从项目陈列变成导购 |
| P2 | 每个 section 增加轻 CTA | 缩短咨询路径 |
| P2 | 资讯内容改为车主知识优先 | 让内容承担 SEO 和信任 |
