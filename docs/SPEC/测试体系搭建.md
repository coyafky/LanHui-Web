# 修复 L13Product：为产品页建立页面级测试覆盖体系

当前产品页测试覆盖严重不均衡：

- 目前只有 `src/app/product/car-care/page.test.tsx` 有页面级测试

- 产品路由 source of truth 是 `src/lib/product-routes.ts`

本次目标不是给每个页面写脆弱快照，而是建立一套低维护、可扩展、能防止产品页空白/路由漂移/核心结构缺失的测试体系。

## 当前已知代码情况

重点参考：

- `src/app/product/car-care/page.test.tsx`
  - 已有页面级测试写法
  - mock 了 `Header` / `Footer`
  - 测试页面渲染、核心组件、JSON-LD

- `src/lib/product-routes.ts`
  - 包含：
    - `ALL_BRANDS`
    - `ALL_MODELS`
    - `ALL_SERVICES`
    - `getLiveBrands()`
    - `getLiveServices()`
  - 应作为产品页测试覆盖清单的数据源

- `src/app/product/**/page.tsx`

  - 服务类页面
  - 品牌页
  - 车型页
  - 动态页面，例如 `window-film/[packageSlug]/page.tsx`

## 修复目标

请建立产品页测试覆盖机制，满足：

1. 所有 live 产品页至少有页面级 smoke test
2. 产品路由清单与实际 `page.tsx` 文件一致
3. 新增产品页时，如果没有测试，CI 能发现
4. 测试关注结构和关键内容，不做大面积 snapshot
5. 不要求 planned / hidden 页面必须作为公开页面测试，除非它仍然实际暴露

- 不要使用 `any`
