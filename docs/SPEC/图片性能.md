```markdown
# 修复 P1-4：产品专题页图片性能账单与 LCP 优化

## 问题背景

当前产品专题页存在明显图片性能问题：

- 多个产品专题页使用 1448×1086 PNG 大图
- `public/images/products` 下大量 PNG 没有 WebP / AVIF 变体
- `next.config.ts` 虽然配置了：

```ts
images: {
  formats: ["image/avif", "image/webp"]
}
```

但这依赖 Next.js Image Optimization on-demand，首次访问仍需要服务端处理图片，容易拖慢 LCP。

已知性能问题页面：

- `/product/flooring`
  - Lighthouse Performance 约 59
  - LCP 约 6.6s

- `/brand/certifications`
  - Lighthouse Performance 约 63
  - LCP 约 6.0s

- `/product/wenjie`
  - 30+ 产品图 / 占位图相关内容
  - 当前存在 `generated-preview` / `pending-review` 图片状态
  - 页面图片数量和首屏加载策略需要优化

## 当前已知代码情况

重点检查：

- `next.config.ts`
  - 已配置 `images.formats = ["image/avif", "image/webp"]`
  - 已配置 `minimumCacheTTL`

- `public/images/products/**`
  - 当前大量图片为 PNG
  - 需要统计 PNG / WebP / AVIF 数量和体积

- `src/app/product/flooring/page.tsx`
  - 首屏 Hero 使用 flooring 图片
  - 可能是 `/product/flooring` LCP 主要来源

- `src/lib/flooring-products.ts`
  - 当前 flooring 图片路径多为 `/images/products/flooring/.../*.png`

- `src/lib/wenjie-preview-images.ts`
  - 当前使用 1448×1086 图片规格
  - 存在 `generated-preview` 状态

- `src/components/wenjie/**`
- `src/components/*ProjectGrid.tsx`
- `src/components/*Hero.tsx`
  - 检查 `Image` 的 `sizes`、`priority`、`loading`、首屏图片策略

## 修复目标

请建立一套产品图片性能优化方案，优先修复高风险页面，并形成长期防回归机制。

目标：

1. 降低 `/product/flooring` 首屏 LCP
2. 降低 `/brand/certifications` LCP
3. 减少产品页对大体积 PNG 的直接依赖
4. 为产品图生成 WebP 变体
5. 修正首屏图片 `priority` / `sizes` 使用
6. 避免下屏产品图抢占首屏带宽
7. 增加图片性能预算检查脚本

## 实现要求

### 1. 新增图片资产审计脚本

新增：

`scripts/audit-product-images.mjs`

使用 `sharp` 读取图片 metadata，扫描：

```text
public/images/products/**
public/images/brand/**
public/images/certifications/**
```

输出：

- 图片总数
- PNG 数量
- WebP 数量
- AVIF 数量
- 超过 300KB 的图片
- 超过 1200px 宽的图片
- 没有 WebP 变体的 PNG
- 可能影响 LCP 的首屏候选图

在 `package.json` 增加：

```json
{
  "scripts": {
    "audit:images": "node scripts/audit-product-images.mjs"
  }
}
```

### 2. 新增图片变体生成脚本

新增：

`scripts/generate-product-image-variants.mjs`

要求：

- 使用项目已有 `sharp`，不要新增依赖
- 对产品 PNG 生成 WebP 变体
- 默认质量：
  - WebP: quality 78-82
  - AVIF: 可选，quality 45-55
- 保留原始 PNG，不删除原图
- 输出路径建议：

```text
public/images/products-optimized/<same-relative-path>.webp
```

或在原目录旁边生成：

```text
image.png
image.webp
image.avif
```

默认建议：**同目录生成 `.webp`**，迁移成本最低。

示例：

```text
public/images/products/flooring/图片/理想/1.png
public/images/products/flooring/图片/理想/1.webp
```

脚本应支持：

```bash
npm run images:variants
```

在 `package.json` 增加：

```json
{
  "scripts": {
    "images:variants": "node scripts/generate-product-image-variants.mjs"
  }
}
```

### 3. 优先修复 `/product/flooring`

重点修改：

- `src/app/product/flooring/page.tsx`
- `src/lib/flooring-products.ts`

要求：

- 首屏 Hero 图优先使用 WebP 版本
- Hero 图片保留 `priority`
- Hero 图片 `sizes` 必须匹配实际布局，不要无脑 `100vw`
- 下屏 gallery / vehicle group 图片必须 lazy load
- 下屏图片不要设置 `priority`
- 如果一个页面首屏只需要 1 张 LCP 图，不要给多个图片设置 `priority`

建议：

```tsx
<Image
  src="/images/products/flooring/图片/理想/1.webp"
  alt="..."
  fill
  priority
  sizes="(min-width: 1024px) 50vw, 100vw"
/>
```

### 4. 修复 `/brand/certifications`

重点检查：

- `src/app/brand/certifications/page.tsx`
- `src/lib/certifications.ts`
- 相关证书图片目录

要求：

- 找出 Lighthouse LCP 元素
- 如果 LCP 是图片：
  - 生成 WebP 版本
  - 修正 `sizes`
  - 首屏唯一 LCP 图使用 `priority`
- 如果 LCP 是文本或大块布局：
  - 检查是否有阻塞渲染的大图、过多阴影、过深首屏结构
  - 不做大规模视觉重构，只修 LCP 相关原因

### 5. 优化 `/product/wenjie`

重点修改：

- `src/lib/wenjie-preview-images.ts`
- `src/components/wenjie/**`
- `src/components/wenjie/model/**`

要求：

- 不要一次性把 30+ 图片都作为首屏资源加载
- 首屏 Hero 图片可以 `priority`
- 产品网格图片必须 lazy load
- 产品网格的 `sizes` 应按卡片宽度设置，例如：

```tsx
sizes="(min-width: 1280px) 25vw, (min-width: 768px) 33vw, (min-width: 640px) 50vw, 100vw"
```

- 对 `generated-preview` / `pending-review` 状态：
  - 如果有真实图片路径，生成 WebP 变体并更新路径
  - 如果只是占位状态，不要加载重型占位图
  - 优先使用轻量 CSS placeholder 或低体积 WebP placeholder

注意：本次不要解决“是否真实施工图”的内容策略问题，只处理图片性能。

### 6. 调整 Next/Image 使用规则

全项目产品图组件统一遵守：

- 首屏 LCP 图：
  - 最多 1 张 `priority`
  - 明确 `sizes`
  - 使用 WebP 源图优先

- 下屏产品图：
  - 不设置 `priority`
  - 保持默认 lazy loading
  - 明确 `sizes`
  - 不要使用 1448px PNG 作为唯一源图

- 小缩略图：
  - 使用较小尺寸源文件或 WebP
  - 不要让 64px 缩略图加载 1448px PNG

## 防回归脚本

新增：

`scripts/check-image-performance-budget.mjs`

检查：

1. `public/images/products/**/*.png` 中超过 300KB 的图片必须有同名 `.webp`
2. 产品页组件中的 `Image` 必须有 `sizes`
3. 同一页面不允许多个疑似 Hero 图片同时 `priority`
4. 产品网格组件中不允许设置 `priority`
5. `src/lib/**/*products.ts` 中新增 PNG 路径时，必须存在对应 WebP 变体

在 `package.json` 增加：

```json
{
  "scripts": {
    "check:image-budget": "node scripts/check-image-performance-budget.mjs"
  }
}
```

如果风险可控，把它加入 `npm run check`；否则先作为独立检查命令。
